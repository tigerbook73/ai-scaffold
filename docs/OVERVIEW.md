# AI Skills — Project Overview

## What it is

AI Skills is a **local skill library** that uses Claude Code commands (`.md` files) as its unit of distribution, delivering skills to any project's `.claude/commands/aisk/` directory with a single `/aisk/sync` command.

Core idea: skills are maintained centrally in a local repository — change once, use everywhere. New skills are promoted to the global library via `/aisk/create-skill`.

---

## Overall Architecture

```
Local skill repository/
├── skills/              ← skill source files
├── claude/setting.json  ← sync configuration
└── ...

  ↓ npm run register (new machine, one-time)

~/.ai-skills/config.json          ← records the repository path
~/.claude/commands/aisk/          ← global meta-commands (/aisk/sync, /aisk/create-skill)

  ↓ /aisk/sync (run inside the target project)

{project}/.claude/commands/aisk/  ← synced skill commands
{project}/.ai-skills/             ← resource files written by sync + runtime context generated by skills
```

**Three layers:**

| Layer | Location | Description |
|-------|----------|-------------|
| Repository | `{repo}/` | Skill source files, maintained centrally |
| Global | `~/.ai-skills/`, `~/.claude/commands/aisk/` | Config + meta-commands |
| Project | `.claude/commands/aisk/`, `.ai-skills/` | Synced skill copies and resources |

## Repository Directory Structure

```
{repo}/
├── skills/                        ← all skill files (commands + resources), organized by group
│   ├── sync.md
│   ├── create-skill.md
│   ├── ...                          ← other meta-commands
│   ├── arch/
│   │   ├── refresh-arch.md
│   │   ├── check-arch.md
│   │   └── README.md              ← arch skill group design doc
│   └── task/
│       ├── prepare-task.md
│       ├── close-task.md
│       ├── README.md              ← task skill group design doc
│       └── resource/
│           └── task-planning.md  ← task workflow rules (synced to .ai-skills/)
├── claude/
│   └── setting.json               ← sync configuration (read by sync.ts, generated by npm run build)
├── scripts/
│   ├── setup.ts                   ← global initialization (one-time)
│   ├── sync.ts                    ← sync implementation
│   ├── create-skill.ts            ← promote a local skill to the global repository
│   └── build.ts                   ← scan skills/ to generate setting.json
├── package.json
└── docs/
    └── OVERVIEW.md                ← this document
```

> **Tech stack**: All scripts use TypeScript, invoked via `npm run <command>`, executed at runtime by `tsx`, with CLI argument parsing via CAC.

## Post-sync Project Structure

After running `/aisk/sync`, the relevant directories in the target project:

```
project/
├── .claude/
│   └── commands/
│       └── aisk/                      ← skill commands (README.md is not synced)
│           ├── sync.md
│           ├── create-skill.md
│           ├── refresh-arch.md
│           ├── check-arch.md
│           ├── prepare-task.md
│           ├── close-task.md
│           └── ...
└── .ai-skills/
    └── task/
        └── resource/
            └── task-planning.md  ← copied from the repository by sync (task workflow rules)
```

After syncing, skills are invoked via `/aisk/refresh-arch`, `/aisk/prepare-task`, etc.

`.ai-skills/` content comes from two sources:

- **Written by sync**: resource files under `skills/task/resource/` (synced to the project with `/aisk/sync`)
- **Generated at runtime by skills**: `architecture.md` (written by `refresh-arch`, not via sync)

## npm Scripts Summary

| Command | Implementation | Purpose |
|---------|---------------|---------|
| `npm run register` | `scripts/setup.ts` | Global initialization (run once on a new machine) |
| `npm run sync` | `scripts/sync.ts` | Sync skills to the target project (usually called by `/aisk/sync`) |
| `npm run build` | `scripts/build.ts` | Scan `skills/` and regenerate `claude/setting.json` |
| `npm run create-skill` | `scripts/create-skill.ts` | Write a skill file to `skills/` and update `setting.json` (usually called by `/aisk/create-skill`) |

> **Runtime dependency**: All scripts are executed as TypeScript via `tsx`; CLI argument parsing uses CAC.

## Management Scripts

### scripts/setup.ts

**Purpose**: Global initialization, run once on a new machine.

**Operations:**

1. Write the current repository path to `~/.ai-skills/config.json`
2. Copy the two meta-commands `sync.md` and `create-skill.md` to `~/.claude/commands/aisk/`, making them globally available across all projects

**Invocation:**

```bash
npm run register
```

---

### scripts/sync.ts

**Purpose**: Sync files from `skills/` to the target project according to `setting.json`.

**Logic:**

1. Read `~/.ai-skills/config.json` → get the repository path
2. Read `{repo}/claude/setting.json` → get the file list; each entry contains `src` and `dst`
3. Copy `{repo}/skills/{src}` to `{target}/{dst}`, overwriting existing files (create directories as needed)
4. If `{target}/.ai-skills/` does not exist, prompt whether to add it to `.gitignore` (yes/no)
5. Output the sync summary (how many files added / overwritten)

**Options:**

```bash
npm run sync                         # sync to current directory, overwrite directly
npm run sync -- --target <dir>       # specify target project directory
npm run sync -- --dry-run            # preview changes without writing
```

**Called indirectly by the `/aisk/sync` command** (see below); users do not typically run this directly.

---

### scripts/create-skill.ts

**Purpose**: Write a skill file to the global repository `skills/` and automatically update `setting.json`.

**Parameters (via CAC):**

```bash
npm run create-skill -- <file> [--name <n>] [--description <desc>] [--force]
```

| Parameter | Description | Default |
|-----------|-------------|---------|
| `<file>` | Source file path (required) | — |
| `--name` | Skill name (target filename without `.md`) | taken from source filename |
| `--description` | Skill description | taken from the first `#` heading in the file |
| `--force` | Skip conflict confirmation for duplicate names | false |

**Logic:**

1. Read `~/.ai-skills/config.json` → get the repository path
2. Determine target path: `{repo}/skills/{name}.md`
3. If the target already exists and `--force` is not passed, output a warning and require confirmation
4. Copy the source file to the target path
5. Call `npm run build` to regenerate `setting.json`
6. Output confirmation (target path, prompt to run `git commit` to persist)

**Called indirectly by the `/aisk/create-skill` command**; users do not typically run this directly.

---

### scripts/build.ts

**Purpose**: Scan the `skills/` directory and automatically generate `claude/setting.json`.

**Logic:**

1. Recursively enumerate all `.md` files under `skills/`
2. Skip `README.md`
3. For each file, infer `dst` based on path conventions:
   - `*/resource/**` → `.ai-skills/*/resource/` (resource files)
   - All other `.md` → `.claude/commands/aisk/` (skill commands)
4. `description`: taken from the first `#` heading; `category`: inferred from directory (`arch/` → `arch`, `task/` → `task`, root → `meta`)
5. If the entry already exists in `setting.json`, preserve its existing `description` and `en` values (do not overwrite manual changes); `category` is always re-inferred from the path
6. Write to `claude/setting.json` and output a change summary (how many entries added / updated / removed)

**Invocation:**

```bash
npm run build
```

Run in these situations: after adding or removing files in `skills/`, or during initial setup.

## Managing Skills

### /aisk/sync

**Invocation**: Run `/aisk/sync` in Claude Code in any project

**Effect**: Reads the global config, calls `sync.ts`, and syncs all skills to the current project.

**Flow:**

```
Read ~/.ai-skills/config.json
  → npm --prefix {repo} run sync -- --target {project-dir}
  → all files recorded in setting.json appear in .claude/commands/aisk/ and .ai-skills/
```

**Installation path**: `~/.claude/commands/aisk/sync.md` (installed by `setup.ts`, globally available)

---

### /aisk/create-skill

**Invocation**: `/aisk/create-skill <file-path>` or `/aisk/create-skill <skill-name>`

**Effect**: Promotes a skill to the global repository so it can be distributed to other projects via `/aisk/sync`.

**Two input modes:**

| Mode | Argument form | Behavior |
|------|--------------|---------|
| File path | Path to an existing `.md` file | Passed directly to `create-skill.ts` for processing |
| Skill name | Plain name (e.g. `my-skill`) | Claude generates the content based on conversation context, writes it directly to `{repo}/skills/{name}.md`, then calls `npm run build` |

**Flow (file path mode):**

```
Read ~/.ai-skills/config.json
  → npm --prefix {repo} run create-skill -- <file> [--name <n>] [--force]
  → setting.json is automatically updated (create-skill.ts calls npm run build internally)
```

**Flow (skill name mode):**

```
Read ~/.ai-skills/config.json
  → Claude generates skill content, writes directly to {repo}/skills/{name}.md
  → npm --prefix {repo} run build
  → setting.json is automatically updated
```

After execution, manually `git commit` in the ai-skills repository to persist.

**Installation path**: `~/.claude/commands/aisk/create-skill.md` (installed by `setup.ts`, globally available)

## claude/setting.json

The sync configuration file and the data source for `sync.ts`; describes which files participate in sync and their target paths.

> This file is auto-generated via `npm run build` and does not need to be maintained manually. Generation rules:
>
> - `*/resource/**` → `.ai-skills/*/resource/` (resource files)
> - `README.md` → excluded (design docs, not synced)
> - All other `.md` → `.claude/commands/aisk/` (skill commands)

**Format:**

```json
{
  "version": "1.0",
  "files": [
    {
      "src": "sync.md",
      "dst": ".claude/commands/aisk/sync.md",
      "description": "Sync global skills to the current project",
      "category": "meta"
    },
    {
      "src": "arch/refresh-arch.md",
      "dst": ".claude/commands/aisk/refresh-arch.md",
      "description": "Generate or refresh the architecture decision document",
      "category": "arch"
    },
    {
      "src": "task/resource/task-planning.md",
      "dst": ".ai-skills/task/resource/task-planning.md",
      "description": "Task workflow rules",
      "category": "task"
    }
  ]
}
```

- `src`: source path relative to the `skills/` directory
- `dst`: path in the target project (relative to the project root); any directory is supported
- `category`: skill category (`meta`, `arch`, `task`)

After adding or removing skills, run `npm run build` to regenerate this file, then `git commit`.

## Typical Workflows

**Initialize on a new machine:**

```
git clone .../ai-skills ~/code/ai-skills
cd ~/code/ai-skills && npm install && npm run register
```

**Enable skills in a new project:**

```
/aisk/sync
```

**Promote a temporary skill to a global skill:**

```
/aisk/create-skill .claude/commands/aisk/my-experiment.md
# → git commit in the ai-skills repository
# → /aisk/sync in other projects
```
