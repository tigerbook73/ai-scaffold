# smart-review

对指定文件、模块或目录进行迭代式审查和修复。

---

## 约束

- **必须使用 agent/subagent 模式执行审查与修复**：扫描目标、识别问题、修复有明确答案的问题都放到独立 agent 中完成，避免大量代码和 diff 污染主上下文
- [写操作] 仅写入指定目标范围内的文件；修改范围外的文件需获得用户明确授权
- 免除全局 Plan Gate —— 无需进入 Plan Mode 即可进行修改

## 输入

`$ARGUMENTS`：`<target-path> [自然语言描述]`

- 目标路径：文件、模块或目录
- 自然语言描述（可选）：指定审查重点（如 "专注于类型一致性"、"仅关注安全问题"）
- 若未提供描述，模型根据目标文件类型自行决定审查重点

若 `$ARGUMENTS` 为空，提示用户指定审查目标，然后停止。

## 步骤

### 第零步 — 启动审查 agent

除非用户明确说"不要用 agent"或当前运行环境没有 agent/subagent 能力，否则必须先启动一个独立 agent 执行第一步和第二步。该 agent 在整个循环期间保持存活：每轮结束后若有需要用户确认的事项，主 agent 收集答案后**续接同一个 agent**（而非重新启动）进入下一轮。

给审查 agent 的任务：

1. 目标路径、自然语言描述（审查重点，若无则按文件类型自行判断）
2. 写操作范围限制：仅写入目标范围内的文件
3. 执行第一步（审查）与第二步（分类与处理）
4. 只返回结构化摘要，不返回完整代码或完整 diff

审查 agent 每轮返回格式：

```text
round: <N>
status: continue | done                  # done：本轮新问题数为 0，或已完成第 3 轮
fixed:
  - file: <path>
    location: <行号或范围>
    change: <一句话描述改了什么>
needs_decision:
  - issue: <一句话描述问题>
    context: <为什么这是需要决策而非直接修复>
    options:
      - <可选方案 A>
      - <可选方案 B>
deferred:
  - issue: <一句话描述问题>
    reason: <依赖上下文 / 信息不足，推迟原因>
out_of_scope_requests:
  - file: <目标范围外的文件路径>
    reason: <为什么修复需要触及该文件>
new_issues_count: <本轮新发现问题数>
```

### 第一步 — 审查

扫描目标，根据自然语言描述（或文件类型）确定审查维度，识别所有问题。

- 目标范围外的文件可读取作为上下文，但不得修改

### 第二步 — 分类与处理

- 有明确答案（逻辑错误、类型错误、格式问题、明显遗漏等）→ 立即修复（仅限目标范围内），记入 `fixed`
- 需要决策（多种有效方案、接口设计影响、业务权衡）→ 不在 agent 内直接提问，记入 `needs_decision`
- 不确定（依赖上下文、需要更多信息）→ 记入 `deferred`
- 修复需要修改目标范围外的文件 → 记入 `out_of_scope_requests`，不擅自修改

### 第三步 — 主 agent 确认与续接

主 agent 收到审查 agent 每轮的返回后：

1. `needs_decision` 非空 → 逐条向用户提问，等待回答
2. `out_of_scope_requests` 非空 → 逐条询问用户是否授权
3. 若上述均为空，或已收集到回答/授权结果 → 续接同一审查 agent，传入决策与授权结果（若有），令其应用后回到第一步重新审查

`status: done` 时不再续接，直接进入第四步。

### 第四步 — 收尾

主 agent 基于各轮审查 agent 返回的结构化摘要直接汇总，无需重新读取代码：

- 汇总所有已做变更：列出每处变更的文件、位置和内容（来自各轮 `fixed`）
- 将所有剩余问题一并列出，注明每项的原因（需要决策未回应 / 信息不足 / 超出范围未获授权）
