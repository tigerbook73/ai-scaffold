# ui-coverage

## 干什么的

`ui-coverage` 提供 UI 变更的测试覆盖规范，约束 `src/` 下的 UI 文件（components、app、context）。回答"改了 UI 之后要做什么"。

规则包含三部分：

- **关键变更判定表**：明确哪些 UI 变更需要测试（新增/删除关键元素、新增完整用户流程等），哪些豁免（纯展示性变更、样式微调）
- **测试类型选择**：关键工作流 → E2E（Playwright）；组件内部交互逻辑复杂 → 组件测试
- **检查义务**：修改 UI 文件时，必须扫描测试文件、判断是否触发关键变更、汇报结论，禁止静默跳过

## 怎么用

安装后，Claude 在修改 UI 文件时会自动：

1. grep 测试文件，确认是否有现存测试覆盖当前组件/页面
2. 对照判定表，判断本次变更是否触发测试要求
3. 若触发但无测试，主动提示用户并说明建议的测试方向
4. 若触发且有测试，检查现存定位器是否因 UI 变更失效

## 组件

- Rule：`rules/ui-coverage.md`

## 注意事项

- 规则激活于 `src/components/**/*.tsx`、`src/app/**/*.tsx`、`src/context/**/*.tsx`，路径不符合时不生效。
- 豁免情形需在 PR/commit message 中注明原因。
- 本 unit 无依赖，可独立安装。通常与 `playwright` 和 `ui-testability` 配合使用效果更好。
