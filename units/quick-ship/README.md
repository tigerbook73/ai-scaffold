# quick-ship

## 干什么的

`quick-ship` 用于处理简单、低风险的工作区变更。它会审查当前 diff，推断改动意图，并在确认后自动完成私有分支创建、提交、开 PR、squash 合并、返回原分支和 pull。

该单元适合文档、配置、样式、轻量措辞或已有测试覆盖的小改动。不适合复杂业务逻辑、新算法、非平凡控制流或需要人工处理冲突的变更。

## 怎么用

1. 确保当前工作区中的变更就是要发布的内容。
2. 在 agent 对话中自然语言请求使用 `quick-ship`，例如：`使用 quick-ship 发布当前变更`。
3. agent 会读取 `git diff HEAD` 和 `git status`，概括意图并判断是否足够简单。
4. 若符合条件，agent 会展示意图、分支名、提交信息、PR 标题和完整操作链。
5. 明确确认后才会执行 git 和 GitHub 操作。

## 组件

- Skill：`skills/quick-ship.md`

## 注意事项

- 执行前只有一次确认提示。
- 任一步骤失败或遇到合并冲突都会立即停止。
- 需要可用的 `git`、远端仓库和 `gh` CLI。
