# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Common Commands

```bash
npm run register                     # One-time setup on a new machine — installs all skills globally
npm run build                        # Scan skills/ and regenerate claude/setting.json
npm run create-skill -- <file>       # Promote a skill file to the global repository
npm run lint                         # ESLint + TypeScript check (scripts/ only)
```

**After modifying skill files or scripts**: run `npm run lint` before committing.  
**After adding or deleting files in `skills/`**: run `npm run build` to regenerate `claude/setting.json`.

## Architecture

Two-layer structure, data flows in one direction:

```
Local skill repository (this repo)
    ↓ npm run register (new machine, one-time)
~/.ai-skills/config.json             ← stores this repo's path
~/.claude/commands/aisk/             ← all skill commands, globally available in every project
```

Skills are available in any project immediately after `npm run register`. No per-project sync needed.

For a new project, run `/aisk/init-project` to configure `.gitignore` and permissions.

## Key Files

- **`claude/setting.json`**: install manifest, auto-generated by `npm run build`. Contains only skill command files (no resource files). Never manually edit the `dst` field; the `description` field is safe to edit manually and is preserved across builds.
- **`scripts/build.ts`**: scans `skills/`, skips `resource/` subdirectories, infers `dst` as `.claude/commands/aisk/{name}.md`. For existing entries, preserves `description`; only overwrites `dst` and `category`.
- **`scripts/setup.ts`**: reads `setting.json` and installs all skill commands to `~/.claude/commands/aisk/`; also writes `~/.ai-skills/config.json` and removes stale global commands.

## Skill File Conventions

- Placed under `skills/`, grouped into subdirectories (`arch/`, `task/`, etc.)
- First line must be `# Title` — the build script uses it to auto-populate the `description` field for new entries
- `README.md` files are automatically skipped and not installed
- Resource files (read by skills at runtime) go in a `*/resource/` subdirectory — they stay in the repo and are read directly via the path in `~/.ai-skills/config.json`; they are not copied anywhere
