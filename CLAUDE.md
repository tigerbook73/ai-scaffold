# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Common Commands

```bash
npm run register                     # One-time setup on a new machine
npm run build                        # Scan skills/ and regenerate claude/setting.json
npm run sync                         # Sync skills to the current directory (usually called via /aisk/sync)
npm run sync -- --target <dir>       # Sync to a specific target directory
npm run sync -- --dry-run            # Preview changes without writing
npm run create-skill -- <file>       # Promote a skill file to the global repository
npm run lint                         # ESLint + TypeScript check (scripts/ only)
```

**After modifying skill files or scripts**: run `npm run lint` before committing.  
**After adding or deleting files in `skills/`**: run `npm run build` to regenerate `claude/setting.json`.

## Architecture

Three-layer structure, data flows in one direction:

```
Local skill repository (this repo)
    ↓ npm run register (new machine, one-time)
~/.ai-skills/config.json      ← stores this repo's path
~/.claude/commands/aisk/      ← global meta-commands (sync.md, create-skill.md)
    ↓ /aisk/sync (run inside the target project)
{project}/.claude/commands/aisk/   ← synced skill commands
{project}/.ai-skills/              ← synced resource files + runtime-generated context
```

## Key Files

- **`claude/setting.json`**: sync manifest, auto-generated by `npm run build`. Never manually edit the `dst` field; the `description` field is safe to edit manually and is preserved across builds.
- **`scripts/build.ts`**: scans `skills/`, infers `dst` by path rule — `*/resource/**` → `.ai-skills/{relPath}`, everything else → `.claude/commands/aisk/{name}.md`. For existing entries, preserves `description`; only overwrites `dst` and `category`.
- **`scripts/sync.ts`**: reads `setting.json`, copies `skills/{src}` to `{target}/{dst}`; on first sync (when `.ai-skills/` doesn't yet exist) prompts to add it to `.gitignore`.
- **`scripts/setup.ts`**: installs only `sync.md` and `create-skill.md` as global meta-commands; all other skills are distributed via sync.

## Skill File Conventions

- Placed under `skills/`, grouped into subdirectories (`arch/`, `task/`, etc.); files at the root are the `meta` category
- First line must be `# Title` — the build script uses it to auto-populate the `description` field for new entries
- `README.md` files are automatically skipped and not synced
- Resource files (read by skills at runtime, not usable as commands) go in a `*/resource/` subdirectory
